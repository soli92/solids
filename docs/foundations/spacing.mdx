# Spacing

Lo spacing in SoliDS è basato su una **scala numerica** in `base.json` (es. `--sd-space-1` … `--sd-space-6`, fino a valori più grandi) e su **alias semantici** in `semantic.json` (es. `--sd-space-xs` … `--sd-space-3xl`) che mappano su passi della scala.

L’obiettivo è:

- ridurre variazioni arbitrarie
- migliorare l’allineamento
- rendere il layout prevedibile e scalabile

---

## Regole fondamentali

- ✅ Usa **solo** valori della scala (`var(--sd-space-*)` o alias `--sd-space-xs` …)
- ❌ Evita `px` arbitrari nei componenti
- ✅ Preferisci token semantici allo spacing “ad hoc”

---

## Scala di esempio (token numerici)

| Token | Uso tipico |
| ----- | ---------- |
| `--sd-space-0` | reset / collapse |
| `--sd-space-1` | gap minimo (4px) |
| `--sd-space-2` | padding interno stretto (8px) |
| `--sd-space-3` | separazione elementi (12px) |
| `--sd-space-4` | layout standard (16px) |
| `--sd-space-5` | respiro medio (20px) |
| `--sd-space-6` | separazioni più ampie (24px) |

La lista completa (fino a `--sd-space-64`, più `px` / frazioni) è in `dist/tokens/tokens.json` e in `dist/css/variables.css`.

## Sistema di spaziatura Material 3 (8dp)

Da Google I/O 2026 Material ha un sistema di spaziatura a token su scala **8dp**, con `space100 = 8dp`
e gli altri token come moltiplicatori (`space250` = 8 × 2.5 = 20dp). SoliDS lo espone con i nomi M3
(`md.sys.measurement.spaceXXX` → `--sd-measurement-spaceXXX`), accanto alla scala numerica, che resta invariata.

| Token | Valore | Token | Valore |
| ----- | ------ | ----- | ------ |
| `--sd-measurement-space0` | 0px | `--sd-measurement-space250` | 20px |
| `--sd-measurement-space25` | 2px | `--sd-measurement-space300` | 24px |
| `--sd-measurement-space50` | 4px | `--sd-measurement-space400` | 32px |
| `--sd-measurement-space75` | 6px | `--sd-measurement-space450` | 36px |
| `--sd-measurement-space100` | 8px | `--sd-measurement-space500` | 40px |
| `--sd-measurement-space125` | 10px | `--sd-measurement-space600` | 48px |
| `--sd-measurement-space150` | 12px | `--sd-measurement-space700` | 56px |
| `--sd-measurement-space175` | 14px | `--sd-measurement-space800` | 64px |
| `--sd-measurement-space200` | 16px | `--sd-measurement-space900` | 72px |

Regole M3 da seguire con questi token:

- **Padding** (spazio dentro un elemento), **gap** (tra elementi di un contenitore) e **margin** (fuori da un elemento).
- **Prima padding e gap, poi margin**: definisci padding e gap sul contenitore padre, non margin sui figli.
- Le posizioni sono `top`, `bottom`, `leading`, `trailing`: usa le proprietà logiche (`padding-inline-start`, …) così leading e trailing si invertono in RTL.
- **Con il testo ingrandito al 200 % la spaziatura resta la stessa.**
- Se manca un valore, aggiungi un token con lo stesso schema (`space225` = 18px) invece di un `px` libero.
- La densità si applica solo su scelta dell'utente: ogni passo (−1, −2, −3) toglie circa 4px di padding verticale, e il target resta almeno 48×48.

In Tailwind v4: `p-(--sd-measurement-space200)`, `gap-(--sd-measurement-space150)`.

## Breakpoint Material 3

I breakpoint (prima chiamati *window size classes*) sono in `base.json` → `--sd-breakpoint-*`.
Le variabili CSS non funzionano dentro `@media`: servono per JS e per la documentazione.

| Breakpoint | Larghezza | Pannelli consigliati | Variante Tailwind v4 |
| ---------- | --------- | -------------------- | -------------------- |
| compact | < 600px | 1 | (default) |
| medium | 600–839px | 1 (2 se il contenuto è poco denso) | `medium:` |
| expanded | 840–1199px | 2 | `expanded:` |
| large | 1200–1599px | 2 | `large:` |
| extra-large | ≥ 1600px | 2 (fino a 3) | `extra-large:` |

Le varianti si aggiungono a `sm:`/`md:`/`lg:`/`xl:`/`2xl:` di Tailwind, che restano quelle di prima.
Per passare da un breakpoint all'altro, M3 suggerisce di chiedersi cosa rivelare, dividere,
ridimensionare, riposizionare e scambiare (es. navigation bar → navigation rail da medium). In ogni
breakpoint le righe di testo vanno tenute tra 40 e 60 caratteri.

export function SpacingScale() {
  const items = [
    { name: "space-0", var: "--sd-space-0" },
    { name: "space-1", var: "--sd-space-1" },
    { name: "space-2", var: "--sd-space-2" },
    { name: "space-3", var: "--sd-space-3" },
    { name: "space-4", var: "--sd-space-4" },
    { name: "space-5", var: "--sd-space-5" },
    { name: "space-6", var: "--sd-space-6" }
  ];

return (
<div style={{ display: "flex", flexDirection: "column", gap: 12 }}>
{items.map((item) => (
<div
key={item.var}
style={{
            display: "flex",
            alignItems: "center",
            gap: 12,
            color: "var(--sd-color-text-primary)"
          }} >
<div style={{ width: 120, fontSize: 12 }}>
{item.name}
<div style={{ opacity: 0.6 }}>{item.var}</div>
</div>

          <div
            style={{
              height: 16,
              width: `var(${item.var})`,
              minWidth: 1,
              background: "var(--sd-color-intent-info)",
              borderRadius: 4
            }}
          />

          <div style={{ fontSize: 12, opacity: 0.6 }}>
            var({item.var})
          </div>
        </div>
      ))}
    </div>

);
}
