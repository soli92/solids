# Getting Started

Come usare **SoliDS** in un progetto in pochi passaggi.

## 1. Installazione

```bash
npm install @soli92/solids
```

## 2. Importa il CSS

Entrypoint completo (consigliato):

```css
@import "@soli92/solids/css/index.css";
```

Include variabili, override per **dark**, **fantasy**, **cyberpunk**, **90s-party**, **steampunk** e temi **personaggio**, layer shadcn, base e utilities. I default **light** / **dark** seguono una lettura **Material Design 3** (superfici tonali, raggi generosi, ombre a livelli), con primary blu allineato a shadcn. Ordine e contenuti: pagina **Foundations / Tokens**.

## 3. Scegli il tema

Imposta l’attributo su `<html>` (o `:root`):

```html
<html data-theme="light"></html>
<html data-theme="dark"></html>
<html data-theme="fantasy"></html>
<html data-theme="cyberpunk"></html>
<html data-theme="90s-party"></html>
<html data-theme="steampunk"></html>
```

Senza `data-theme`, il **dark** di sistema (`prefers-color-scheme`) applica i token dark; **fantasy**, **cyberpunk**, **90s-party**, **steampunk** e i temi **personaggio** restano espliciti. Dettagli: **Foundations / Themes**; accessibilità, motion e font stack: **Foundations / Accessibility and Motion**.

Con **next-themes**, usa `attribute="data-theme"` e valori come in `docs/shadcn-integration.md` (inclusi i temi **personaggio**). Per comparire tutti nel selettore, estendi `themes` su `ThemeProvider`.

## 4. Tailwind + shadcn (opzionale ma consigliato)

**Tailwind CSS v4 (consigliato)** — configurazione CSS-first, nessun `tailwind.config`:

```css
/* globals.css */
@import "tailwindcss";
@import "@soli92/solids/css/tailwind.css";
@import "tw-animate-css";
```

`css/tailwind.css` include già i token (`index.css`, dentro `@layer base`), il bridge `@theme inline` (colori shadcn, sidebar, radius, shadow, font, keyframe accordion) e la variante `dark:` per `.dark` e per tutti i temi scuri (`data-theme`). Non importare anche `css/index.css`. Installa `tailwindcss`, `tw-animate-css` e il plugin del tuo bundler (`@tailwindcss/postcss` o `@tailwindcss/vite`).

**Tailwind CSS v3 (legacy)** — il preset resta pubblicato per i progetti esistenti:

```js
// tailwind.config.cjs (o .js)
module.exports = {
  presets: [require("@soli92/solids/tailwind-preset")],
  content: ["./app/**/*.{ts,tsx}", "./components/**/*.{ts,tsx}"],
};
```

Poi `npx shadcn@latest add …` con gli item del registry `@solids`. Guida: `docs/shadcn-integration.md`.

## 6. Dati reali: cosa resta al consumatore

`Item`, `Avatar` e `Badge` reggono stringhe lunghe, senza spazi, in lingue e direzioni miste (`min-w-0`, `overflow-wrap:anywhere`, `dir="auto"` sovrascrivibile su `ItemTitle` e `ItemDescription`, `object-cover` sull'immagine dell'avatar, badge su una riga). Se a 320px o a zoom 200% il contenuto non ci sta, va a capo l'intera riga delle azioni, mai il testo del badge. Il resto è del consumatore, per scelta:

- **Descrizioni troncate:** `ItemDescription` usa `line-clamp-2`. Il valore intero va esposto dal consumatore, ad esempio `<ItemDescription title={email}>`.
- **Nome mancante:** il componente non inventa un titolo. Usa un valore di ripiego (es. l'email) come `ItemTitle`.
- **Iniziali:** `getInitials(nome, max = 2)` da `src/lib/initials.ts` lavora sui grafemi (emoji intere, apostrofi, CJK, arabo) e restituisce `""` se il nome è vuoto: il ripiego (`?`, icona) lo sceglie chi chiama.
- **Plurale:** `Intl.PluralRules` (`1 membro`, `2 membri`), non una stringa cablata.
- **Liste lunghe:** il DS non virtualizza. Con migliaia di righe, paginare o virtualizzare.
